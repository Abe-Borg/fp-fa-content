# CLAUDE.md

Guidance for coding agents working in this repository. Read `docs/prototype-plan.md` first. It is the plan of record and it says what is in and out of v0.

## What this is

+Cynosure: a Windows desktop assistant for hyperscale data-center fire sprinkler and fire-alarm design. It was FP/FA Design Assistant until 2026-11-09; the package, the data directory, and the environment variables keep the `fpfa` name. `app/` is a Python program whose window is a web page in Microsoft Edge WebView2 (Spec Surgeon's stack: a local server, a React page, pywebview). Everything else is a content pack the app loads at runtime: `skills/`, `roles/`, `modes/`, `calcs/`, `corpus/`, `specs/`. Claude writes narrative and reads methods. Every number comes from `calcs/`. The README has the full description.

## Rules that do not bend

- Numbers come from the calc tools. The model never computes gallons, seconds, gpm, psi, scfm, or the releasing table.
- Five statuses are never merged: software hardening, offline regression evidence, installed Windows evidence, live-model evidence, and engineering validation. Only the first two exist. A document, a report, or a commit message that lets one stand for another is wrong. Do not present someone else's reported test counts as runs you made.
- Three labels stay distinct: calculated, ASSUMED, use best judgment. A delivery time is an optimistic screen, not a listed water-delivery-time calculation.
- Scope is wet pipe, dry pipe, double-interlock preaction, the detection and releasing that trip them, and outdoor oil-filled transformer apparatus water spray. Foam, clean agent, water mist, building deluge, single-interlock, and non-interlock are refused. Canada only through a skill's Country gate; CAN/ULC and CEC Section 32 bodies stay NEEDS HOLD.
- NFPA 13-2025 is the delta baseline. An unamended 2024 I-Code adoption enforces NFPA 13-2022 until the adoption is verified. Cite the section and the edition together.
- No raw standards text, no vendor catalog numbers, no job, client, or personal names anywhere in the pack. Tests scan for them and fail the build.
- The double-interlock draft section is 21 13 19. Dry pipe is 21 13 16. Never cross them.
- Release is the detection leg AND P, the pressure drop from sprinkler operation. Low air is supervisory only and is never a release input. `docs/releasing-basis.md` is the basis, and it is unresolved as engineering: no standard was opened and no qualified engineer has reviewed it. Do not write that it was verified, and do not turn a section number a reviewer reported into one that was read. Only `app/fpfa/releasing.py` reads the kernel's deprecated `boolean` and `low_air` names, and a model never sees them; `di_zone.py` has a copy on the content team's side, so do not remove the aliases here alone. `calcs/fp/test_pack_content_lowair.py` and `app/tests/test_releasing_basis.py` read the pack, the docs, and the outputs sentence by sentence. The detector is `releasing.release_wording_hits`, and the pack lint carries a copy of its rules so it can travel with a bare pack: change both together (`test_the_two_detectors_agree_sentence_for_sentence`). It runs on every finding and every lead reply.
- The size exemption is judged on the zone total and exists once: the tool plan hands `dry_delivery_screen` the takeoff's `zone_gal`, and the recorded row is what the narrative, the tile, and both documents print (`workflow.exemption_answer`, `exemption_text`). Never govern a copy in memory. A screen with no zone total is `workflow.pipe_only_screen` and never says the exemption is met.
- Which copy of the skills is authoritative, the packaged one or the content team's live one, is the owner's decision and is not made (`docs/content-provenance.md`). Do not copy either over the other. A correction to a packaged file goes in that page's table with the test that guards it.
- The Messages client sends no `temperature`, `top_p`, `top_k`, or forced `tool_choice`, and never disables thinking. The system text goes out as one cached block. Do not add a second model vendor.
- The content pack is replaceable. Nothing in `app/` hardcodes a method, a role, or a mode. Loaders read them from disk.
- Agents never open the project record directly. A calc tool records itself; a model writes facts, findings, questions, and decisions through the record tools. A `ToolSession` without a record writes nothing, and tests rely on that.
- The project inputs are record facts (`app/fpfa/inputs.py`). The form and the lead's `set_input` write them; a specialist never does. Every basis field goes through `Record.sync_form`, an empty one too: the lead's value is put on an empty field, and a field the designer emptied leaves the record (`Record.clear_given`); never leave a blank field out of the sync. When the sync puts a value on the open job, the form shows it before it is read again and unsaved typing in the other fields stays (`Desk._show_pulled`). A calc that took a figure from an alternative is an alternative (`coherence.analyze`). A finding or a decision is never edited: it is replaced (`replaces`) or withdrawn, and the old row stays as history.
- What the app derives, no model types: what is out of date and why (`coherence.py`), the tier a finding earned (`checker.assurance`), what a design basis is missing (`checker.coverage`), the status block and `/status` (`status.py`), the Team block under a reply, the figures the reply audit could not find (`reply_audit.py`), who read which skill (`content_use.py`), and the Results tab's tiles (`results_panel.py`).
- The record reconciles a change only for the tools in `coherence.BINDINGS` and `DERIVED`. A tool with no entry is not tracked, and every view says so; do not let an untracked path imply it was reconciled. A calc row whose `calc_identity` differs from the installed pack's (`Record.context`, set by `ToolSession` and `Desk._note_content`) is out of date.
- A figure is a number and a kind of unit (`quantities.py`). The trace check and the reply audit both match on the pair. In the reply audit a figure on an out-of-date row is out of date whatever a finding, an earlier message, or an earlier reply says; only a current calc or input, the pack text, a calc or content tool run this turn, and this turn's message make it current.
- A Results tile is a calc tool's output and nothing else. `results_panel.py` prints a field of the tool result with the rounding and the words `workflow.template_narrative` uses, through `fmt1`, `trim_assumption_text`, `screen_limit_assumption_text`, and `releasing.releasing_logic`; it computes nothing, elects nothing the tool did not (the gas fill has two bases and no headline number), and the page formats nothing. `tests/test_results_panel.py` holds each tile to the tool output and to the narrative. `Desk.results_text` stays the run as plain text.
- How the team is run is content: `roles/lead/ROLE.md` and the "Working with the team" section of each specialist's role. `team.py` holds the tools and the plumbing. Nothing in `app/` makes two specialists exchange anything: a `consult`, a review, or an objection exists only when a model made it. Do not add code that manufactures one.
- The record check is a trace check. It says whether a finding is consistent with the rows it cites, and nothing in the app, the docs, or an export may call it verification or say a standard was checked. `checked_against_standard` stays `False`. No tier title may read as verification (`test_no_tier_is_named_as_verification`), and `checker.LADDER` names verification against the primary standard and a qualified engineering review as not performed, on every export. The Design Basis opens with `checker.coverage`: a draft with work missing is exported and says INCOMPLETE DRAFT; never block it for that, and never let it look whole. The Design Basis waits for a current trace check and for nothing out of date (`checker.export_reason`), and prints the tier of every finding; the Section 21 13 19 export keeps its own gate, every claim Supported, and is refused while the form has moved past the run it would be written from.
- A test that involves an agent plays a scripted model. Say so where it is written and where it is reported: a scripted pass shows what the application does, never what the live model does. `docs/acceptance-tests.md` keeps the table of tested, simulated, and unrun.
- An evaluation check has to be able to fail. Before adding one to `live_eval.py`, name what would fool it. A calc row keeps the name of whoever ran it first, so a citation of a row the citing specialist replayed is not collaboration (`live_eval.collaboration`); a bare agreement is not a position; a row marked out of date is not reconciled; a checker that approves everything is not a check (the probe step). A scenario blocked on an owner's confirmation is reported as blocked, not chosen for them.
- A failure does not un-spend what ran before it. A delegation, consult, turn, or check that ends on an error writes its event marked `failed` with the usage that had finished (`claude_client.attach_usage`). A failed request reports no usage; say that, never guess a figure, and never call `--max-usd` or any other guard a spending limit.
- The window is a web page (plan of record, 2026-11-10). `app/fpfa/desk.py` holds every rule the window follows and needs no toolkit; `app/fpfa/web/server.py` serves the page and the API on 127.0.0.1; `app/fpfa/web/shell.py` shows it in WebView2 through pywebview, or in the default browser when there is no backend. The page draws the state and posts actions; it decides nothing about a job. Do not add a second UI stack, bring tkinter back, or move a rule into the page.
- The window is a job list, a thread, and a job panel (plan of record, 2026-11-11). The panel's tabs are Inputs, Results, and Team, as buttons in the one top bar (`#tab-inputs`, `#tab-results`, `#tab-team`); there is no "Zone details" and no drawer, so no string the app writes may send a designer to one. The layout is the page's own (`frontend/src/layout.ts`): the app only remembers the job list shown or hidden, the open tab, and the panel's width (`Desk.set_layout`, `config.json`), and the page reads them once at launch. The panel in the thread's place is for the moment and is not remembered. What is in the panel lays itself out by the panel's width with `@container panel` queries, never by the window's, so it reads the same beside the thread and in its place. The page shows the Results tab when `run_rev` moves; nothing else opens the panel by itself.
- The server stays standard library, bound to 127.0.0.1. Every `/api` request carries the launch token; a foreign Host or Origin is refused. A new action is one entry in `server.ACTIONS` that calls one `Desk` method. Nothing in the page fetches from the network.
- `Desk` state changes only on the desk's thread: an action under `Desk.call` (the server does this) or a callback a worker put on `Desk.queue`, which `pump()` runs. A worker never touches a `Var`, `chat_log`, or a counter. A change bumps `revision` through `_touch()`; the conversation changing goes through `_render_chat()` so `thread_rev` moves too; a form change the page did not make goes through `_form_loaded()`. A native dialog never runs with `Desk.lock` held (`Desk._ask_save`).
- A rule never names a colour. CSS reads a token from `styles.css` or mixes two (`color-mix`); the scheme card previews read a scheme's colours from the state. A new scheme defines every token in `theme.TOKENS`, in `theme.py` and in `styles.css` alike (`tests/test_theme.py` keeps them equal); a new token goes into every scheme.
- A streamed request is the request `create()` sends, byte for byte: same system block, same cache markers, same tools. Do not mark a tool for eager input streaming and do not add a field to one path only. Only the lead's reply is drawn in the thread; a specialist's and the checker's words never are. `FPFA_EFFORT` adds `output_config.effort` in `_prepare`, which both paths share; it is unset by default and nothing in the app sets it.
- The working line names a tool or a file. It never shows a tool's inputs or its result.
- What the pointer can work, the keyboard can. A control that opens a menu is a `MenuButton` (`components/Menu.tsx`), which opens on a click, Space, Enter, or Down and gives the keys back when it closes; a new clickable row or card is a button or takes the focus and answers Space and Enter. The panel's edge is a `separator` that takes the focus and moves with the arrow keys, Home, End, and Enter (`layout.widthAfterKey`). The keyboard's ring is `:focus-visible` only, never `:focus`, which a click sets too.
- The thread follows its end only while `Thread`'s `follow` is true. Every way the reader moves the thread (the wheel up, a key, a press on the scrollbar) calls `moved()` when the move happens, the press and not the release; reaching the end again turns following back on.
- The license is PolyForm Shield 1.0.0. It is stated in `LICENSE`, `app/fpfa/about.py`, `app/packaging/installer.iss`, the Windows workflow's release notes, and the README; `app/tests/test_branding.py` keeps them in step. The installer's license page reads the root `LICENSE`, never a copy, and nothing may skip it or pre-select acceptance. A bundled package with no license text fails the build: supply `app/packaging/third_party_licenses/<name>-<version>.txt`, never silence the check.
- The inbox is in memory; the record is all that survives a relaunch. Window jobs are `jobs` rows there, and `Record.recover()` runs once at launch and only marks: in-flight jobs and agents become `interrupted`, delivered handoffs go back to `pending`. Nothing is re-run on its own. One window per data directory: `Desk` takes the OS file lock on `fpfa.lock` first and a second window is refused. `docs/recovery-protocol.md` is the Test C and D protocol.

## Working here

- Python 3.11 or newer; 3.12 is what the suites are run with. Install `app/requirements.txt` (pywebview included). Node.js 22 builds and tests the page.
- Tests, from the folders named: `calcs/fp`: `python -m unittest discover -s . -p 'test_*.py'`. `calcs/fa`: `python -m unittest discover -s tests`. `app`: `python -m unittest discover -s tests`. `app/frontend`: `npm test`. Run all four before a push and put the counts in the pull request body. `.github/workflows/tests.yml` runs them on every pull request. The browser test in `test_web.py` runs where Node.js can `require('playwright')` and is skipped otherwise.
- After a change under `app/frontend`, run `npm run build` there and commit `app/fpfa/web/static` with it: `test_web.py` compares the build's stamp with a hash of the source and fails on a stale page. `npm ci` installs the exact dependencies; a new npm dependency must ship its license text (`licenses.json`, written by the build).
- Run the app from `app/` with `python -m fpfa`. `--browser` opens the page in the default browser, `--serve --port <n>` serves it and opens nothing, `--demo --quit` runs the sample with no window, and `--demo --quit --screenshot-dir <dir>` writes PNGs of the page through `frontend/tools/shoot.mjs`. `--theme <id>` picks a colour scheme for one run.
- `FPFA_DATA_DIR` moves the data directory. `FPFA_CONTENT_UPDATES=0` skips the launch feed check. `FPFA_CONTENT_ROOT` pins the pack. `FPFA_THEME` picks a scheme and `FPFA_REDUCE_MOTION=1` turns the easing off for one run. `FPFA_EFFORT` sets the model's effort for a run.
- `python -m fpfa.live_eval --out <folder> [--job dh1|dh2]` (or `--live-eval <folder>` on the app) runs the evaluation path against the live model with the saved key, in its own data directory, and is billed. Never run it from a test or a build, and never to see whether a change works: the owner runs it. Its tests inject a scripted client through `Runner(client_factory=...)`.
- A scripted agent is a list of moves in `tests/team_scenario.py` style: `call(use("tool", arg=...))` and `say("text")`, where a move may be a function that reads ids off the record. A turn that involves two agents needs a script per agent; a script with a move left over fails its test.
- A window test opens a desk through `Loop()` (`tests/desk_loop.py`), calls its actions as the page's POSTs would, runs the workers' callbacks with `update()`, and reads `Desk.snapshot()` and `Desk.thread_text()`. A message the app would show in a dialog is a `Desk.notices` entry; a save dialog is `Desk.shell.ask_save_path`, which a test patches. The easing of a reply is the page's (`frontend/tests/reveal.test.ts`); the desk always holds the whole text.
- Look at the window after a change to it: `python -m fpfa --serve` (or the harness of a test) and `node frontend/tools/shoot.mjs <url> <dir> [scheme]`, or drive it with Playwright. Check a light scheme (`linen`) and a device scale above 1. Node's type stripping runs the page's tests: no TypeScript parameter properties or enums in `src/` modules the tests import.
- The key is read once at launch and kept (`Desk._api_key`); Settings refreshes it. Do not call `load_api_key()` on a click path: on a Windows source run it starts a child Python.
- Model prices live only in `usage_report.py` as a dated snapshot (`RATES_PER_MILLION`, `RATES_DATE`). Change both together; never spread a price elsewhere.
- When behavior changes, update `README.md` in the same change. Do not shorten it to make room; add what is necessary. When dependencies change, update `app/requirements.txt`. When a phase, gate, or decision changes, update `docs/prototype-plan.md`. When what was tested, simulated, or unrun changes, update the table in `docs/acceptance-tests.md`. Keep this file current.
- Regenerate `docs/screenshots` after a change the pictures show: `python tests/docs_pictures.py` from `app/` (Node.js with Playwright). They are taken from the scripted scenario, and the README says so.
- One pull request per phase where practical. No release tags from a pull request. Content releases are `content-v*` tags; app releases are `app-v*` tags and need `app/fpfa/__init__.py` to carry the same version. The version is also in `app/packaging/installer.iss`, `app/frontend/package.json`, and `package-lock.json`; the page is rebuilt after it moves. A pack built from this tree asks for this app version or newer (`min_app_version`): `roles/lead` and the roles' team sections need the tools this app has.
- The installer's AppId, the `fpfa` package name, the `FPFA_*` variables, the data directory name, and the keyring service name are not renamed. An existing install and its data depend on them.
- After a change to the star or its colours, run `python packaging/make_icon.py` from `app/` and commit `packaging/assets/Cynosure.ico`.
- The model id is `claude-opus-5-5`. A chat turn streams (`AnthropicMessages.streaming`); everything else calls `create()`. Prompt caching is on the system block and, with tools present, on the message tail. Keep the system text byte-identical across rounds; put anything that varies per turn in the user message, which is where the lead's status block goes. A transient failure is retried up to `RETRY_ATTEMPTS`, waiting the API's `retry-after` up to `RETRY_AFTER_CAP`.
- The target machine is Windows. Keyring goes through Credential Manager there; other desktops use a user-only file. Do not break the frozen-app path in `keystore.py`.

## Content pack rules

- A skill, role, or mode is one folder with one markdown file and frontmatter. The pack build (`scripts/build_content_pack.py`) strips paths named foam, clean-agent, canada, catalog, and `_sources`, and refuses any file that holds an API key.
- Keep section numbers, edition years, and numeric screens. Paraphrase; do not quote a standard at length.
- Do not add a code threshold to `calcs/fa/lib/lfl.py`. Percents are inputs.
